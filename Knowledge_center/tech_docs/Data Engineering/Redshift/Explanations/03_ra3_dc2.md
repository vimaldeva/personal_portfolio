## RA3 Nodes vs DC2 Nodes in Redshift

### What are they?
- These are the two types of compute nodes you can choose when creating a Redshift cluster
- The core difference: where data is stored

Analogy:
- DC2 = A laptop where everything is stored on the laptop itself — fast but limited space
- RA3 = A laptop that stores files on Google Drive — storage is separate, scales independently

---
### DC2 Nodes (Dense Compute)
- Storage is local on the node itself (SSD-based)
- Compute and storage are tightly coupled — you cannot separate them
- To get more storage → you must add more nodes (also adds more compute whether you need it or not)
- Best for fixed, predictable datasets that don't grow much

```
DC2 Node
├── CPU       (yours)
├── RAM       (yours)
└── SSD Disk  (fixed, attached directly to node)

```

| DC2 Type | Storage per Node | Slices |
| :-- | :-- | :-- |
| dc2.large | 160 GB SSD | 2 |
| dc2.8xlarge | 2.56 TB SSD | 16 |

---
### RA3 Nodes (Managed Storage)
- Compute (CPU/RAM) is on the node
- Storage is on AWS Managed Storage (backed by S3) — called RMS (Redshift Managed Storage)
- You can scale compute and storage independently
- Automatically moves hot data to local SSD cache, cold data stays in RMS
- Best for growing datasets or when you want cost control

```
RA3 Node
├── CPU              (on node — fast)
├── RAM              (on node — fast)
├── Local SSD Cache  (hot/frequently accessed data)
└── RMS (S3-backed)  (full data lives here — scales separately)
```

| RA3 Type | Managed Storage per Node | Slices |
| :-- | :-- | :-- |
| ra3.xlplus | Up to 32 TB | 2 |
| ra3.4xlarge | Up to 128 TB | 4 |
| ra3.16xlarge | Up to 512 TB | 16 |

---

### Comparison
| Factor | DC2 | RA3 |
| :-- | :-- | :-- |
| Storage location | Local SSD on node | AWS Managed Storage (S3-backed) |
| Scale storage independently | ❌ No | ✅ Yes |
| Scale compute independently | ❌ No | ✅ Yes |
| Hot/Cold data management | ❌ No | ✅ Auto |
| Performance | Very fast (local SSD) | Fast (cached hot data) |
| Cost for large data | Gets expensive | More cost-efficient |
| Best for | Small-Medium fixed datasets | Large or growing datasets |

---
### Key Things to Remember
- DC2 = pay for compute + storage together, no flexibility
- RA3 = pay for compute and storage separately — more control
- RA3 uses local SSD as a cache — frequently accessed data stays fast
- For new clusters, AWS recommends RA3 by default
- You cannot mix node types in a single cluster
- RA3 supports Redshift Data Sharing (DC2 does not)
- Cross-account and cross-region data sharing only works with RA3

---
### Real-World Use Case

**DC2 scenario**:
A startup has a fixed 500GB dataset that won't grow much. They pick dc2.large — simple, fast, cheap for small scale.


**RA3 scenario**:
An e-commerce company starts with 5TB but grows 1TB every month.
They pick ra3.4xlarge — storage scales automatically without adding compute nodes.  Hot data (last 30 days orders) stays in SSD cache → fast queries. Old historical data stays in RMS → still queryable but cheaper to store.
